# 微博超话签到 · 飞书机器人

把「微博超话一键签到」的全部功能接入**飞书机器人**：用户在飞书里给机器人发消息即可绑定自己的微博、一键签到全部超话；配了**卡密系统**（卡密随机生成、存飞书多维表格）。当前采用**管理员手动发卡**模式：用户「购买」收到收款码付款，管理员核对后发卡。

> 免责声明：本工具仅供学习与个人账号正常签到使用，请遵守微博平台及飞书平台的使用条款与相关法规。请勿用于恶意营销或平台禁止的自动化批量操作。

---

## 一、系统组成

```
飞书用户 ──► 飞书机器人（lark-oapi 长连接 WebSocket）──► 本 Bot 程序
                                                          │
            ┌───────────────┬──────────────┬──────────────┐
            ▼               ▼              ▼
       微博签到模块      卡密系统       飞书多维表格
      (二维码/粘贴cookie) (随机生成)   (卡密存表)
```

- **微博模块**：复用原 Tkinter 版的签到核心逻辑（分页拉取关注超话 → 一键签到 → 状态分析），去掉 GUI 依赖，按用户维度隔离 cookie。
- **卡密系统**：随机生成 **9 位**卡密（字母+数字），激活后绑定飞书用户并计算到期时间。
- **飞书多维表格**：卡密作为记录存在飞书「卡密库 / 卡密表」；未配置飞书时自动落到本地缓存兜底。
- **发卡模式**：管理员手动发卡。用户「购买」收到收款码 → 扫码付款 → 联系管理员 → 管理员 `发卡`。

```

```

## 三、部署步骤

### 1. 安装依赖
```bash
cd weibo_claw_bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. 飞书开放平台配置（关键，约 5 分钟）

登录 [飞书开放平台](https://open.feishu.cn/app)，进入你的自建应用：

1. **凭证与基础信息**：记下 `App ID` / `App Secret`。
2. **应用能力** → 添加能力 → **机器人**（开启机器人对话）。
3. **权限管理** → 添加权限并保存：
   - `im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）
   - `im:message:send_as_bot`（以应用身份发消息）
   - `im:message.group_at_msg:readonly`（群聊@机器人消息，可选）
   - `im:resource`（上传/获取图片资源，用于发二维码）
4. **事件与回调** → 事件配置 → 添加事件 → **接收消息 im.message.receive_v1**；订阅方式选 **使用长连接接收事件**。
   > 必须先启动一次本地 `run.py`（长连接在线）再保存该订阅方式。
5. **版本管理与发布** → 创建版本并发布。**必须发布，事件订阅才生效。**

### 3. 填写 config.json
| 配置项 | 说明 |
|---|---|
| `feishu.app_id / app_secret` | 飞书自建应用的 App ID / App Secret |
| `feishu.app_token` | 「微博签到卡密库」多维表格的 app_token |
| `feishu.card_table_id` | 卡密表的 table_id |
| `admin.feishu_open_ids` | 管理员飞书 `open_id`。让机器人给管理员发一条消息，从日志里拿到 `open_id` 填入即可获得管理权限 |
| `weibo.chromedriver` | 指向原项目里的 `chromedriver.exe`（用于二维码登录；不配置则仅支持粘贴 cookie） |
| `bot.*` | 每日定时签到、主动发送使用说明、每日自动生成卡密的时间 |

> 飞书读写卡密表：需在开放平台给应用开通 bitable 权限并把应用加为该表协作者；未配置时卡密先落本地缓存。

### 4. 启动机器人
```bash
python run.py
```
启动后日志打印 `connected to wss://...` 说明长连接建立成功。用户在飞书里加机器人为好友、发消息即可使用。

## 四、用户在飞书里怎么用

用户给机器人发任意消息，第一次会自动推送使用说明。

| 指令 | 作用 |
|---|---|
| `使用说明` / `帮助` | 查看使用说明 |
| `绑定微博` | 发起微博二维码登录（需微博APP扫码） |
| `绑定cookie <cookie串>` | 粘贴微博登录cookie绑定（兜底） |
| `签到` | 一键签到全部关注超话 |
| `分析` / `状态` | 查看超话签到情况 |
| `购买` / `获取卡密` | 查看卡类型并收到收款码，扫码付款后联系管理员发卡 |
| `兑换 <卡密>` | 激活卡密 |
| `我的卡` | 查看卡密状态与到期时间 |
| `取消` | 停止进行中的任务 |

---

## 五、管理员指令

| 指令 | 作用 |
|---|---|
| `发卡 <类型> <数量>` | 生成卡密，写入飞书表。例：`发卡 month 10` |
| `卡密列表` | 查看最近卡密 |
| `用户列表` | 查看已绑定微博的用户及cookie有效性 |
| `广播 <内容>` | 向所有已认识用户群发 |
| `禁用卡 <卡密>` / `启用卡 <卡密>` | 禁用/启用某张卡 |

`<类型>`：`month`（月卡，20元/月；新用户首月15元）。

## 六、卡密购买与发卡（管理员手动发卡）

**购买流程**
1. 用户发 `购买` / `获取卡密` → 机器人回复卡类型菜单 + 收款码图片（`bot.payment_qr_image`）。
2. 用户扫码付款，并把付款成功截图发给管理员。
3. 管理员核对后，用 `发卡 <类型> <数量>` 生成卡密发给用户。

**每日自动生成卡密（补库存）**
- `bot.daily_card.enabled=true` 时，每天 `hour:minute` 自动生成 `count` 张新月卡写入卡密库（与已有卡不重样），并通知管理员。

---

## 七、主动发送使用说明

- **首触推送**：用户第一次发消息时自动发送（`bot.usage_on_first_contact`）。
- **定时推送**：每日 `bot.proactive_usage_hour/minute` 向已认识用户主动发送使用说明。
- **启动推送**：设置 `bot.proactive_usage_on_start=true`，每次启动向所有已认识用户推一次。

## 八、常见问题

- **机器人收不到消息**：确认应用已开启机器人能力、已订阅 `im.message.receive_v1`、订阅方式为长连接、且已发布版本。
- **绑定微博报错**：二维码登录依赖 Chrome + chromedriver 版本匹配。若不匹配/环境受限，改用 `绑定cookie` 方式。
- **cookie 失效**：微博 cookie 会过期，机器人会提示；重新绑定即可。
- **无法发卡 / 无法购买**：用户购买会收到收款码，付款后联系管理员，管理员用 `发卡` 手动发。
- **飞书读写失败**：检查自建应用是否已发布、权限是否添加、是否给表加了协作者。

## 九、数据与安全

- 微博 cookie、卡密缓存均存于 `storage/`，注意保密，勿提交到公开仓库。
- 卡密表里的 `WB-DEMO-*` 为演示数据，正式上线前请删除。
